# 全局存档与续团

## 导出存档

1. 主持人在房间右侧工具栏打开「全局存档」（移动端先切换到「局内工具」），无需退回准备阶段。
2. 核对面板显示的房间名称、规则版次与角色列表，以及事件记录条数和备团资料摘要。
3. 「导出图片（仅保留路径引用）」默认开启，ZIP 内仅记录图片在服务端 `IMAGE_DIR` 中的引用路径，不打包原图文件。主持人可为图片选填文字说明；若关闭图片开关，则必须为每张图片填写替代文字描述。
4. 点击「选择保存位置并导出 ZIP」（不支持文件保存选择器 API 的浏览器显示「下载全局存档 ZIP」）。系统会截取当前房间的最新状态生成压缩包。

## 恢复存档与认领席位

1. 在首页选择与存档一致的规则与版次。
2. 在「创建房间」页填写主持人称呼，点击「从全局存档续团」并选择导出的 ZIP 文件（无需手动解压）。
3. 核对存档摘要与原房间阶段后，点击「恢复存档，继续故事」。系统会创建新房间并重新生成房间码、会话令牌与一次性席位恢复码。
4. 主持人在「全局存档」面板复制各玩家的席位恢复码，连同新房间码分别发给对应玩家。
5. 玩家选择相同规则与版次，在「加入房间」页输入新房间码、称呼和自己的席位恢复码，即可认领原角色。每个恢复码仅可使用一次。

恢复后的房间完整保留原有的准备或进行阶段，恢复角色数值、局内修正与物品，同时还原当前场景、参战个体和先攻回合进度。

## 存档文件结构

| 文件名          | 内容                                                                                     |
| --------------- | ---------------------------------------------------------------------------------------- |
| `manifest.json` | 存档格式版本（当前为版本 2，兼容版本 1）与导出时间，以及图片开关状态和各文件 SHA-256 校验和 |
| `room.json`     | 房间配置、全体角色与审核状态，外加地图场景库与 NPC / 数据块，以及遭遇进度和全部可用事件历史 |
| `context.md`    | 完整过程文本记录（含暗骰真实结果、图片服务端路径或替代文字说明），可供阅读或外部 AI 使用   |
| `README.md`     | 存档恢复步骤与图片保留期说明                                                             |

存档包含主持人私密备团资料与暗骰真实结果，请由主持人妥善保管。存档不含服务端 API 密钥、登录令牌或图片原文件。导入时服务端会校验格式版本、SHA-256 校验和与大小上限（ZIP 上限 32 MiB，解压后 `room.json` 上限 64 MiB、`context.md` 上限 28 MiB）。

## 历史记录与暗骰遮罩

服务端保存房间的可用事件历史。网页首次打开时加载最近 300 条，点击「加载更早记录」可逐页上翻；聊天区的 Markdown 导出仅包含当前已加载的记录，全局存档 ZIP 则导出全部可用记录。旧版本已经丢弃的记录无法补回。

主持人暗骰在玩家端仅显示投掷时间与骰式或检定名称，点数与结果统一遮罩为「？」。历史翻页与存档恢复后继续保持该遮罩。

## 图片保留期与服务器迁移

- 原图保存在 `IMAGE_DIR`，图片元数据与引用签名保存在 `DATA_DIR/images.json`。迁移或完整备份服务器时，请同时复制 `DATA_DIR` 与 `IMAGE_DIR`。
- 图片在最后一次跑团结束（房间退回准备阶段、关闭房间或全员离线）14 天后自动删除。期间重新开团会重置 14 天计时，进行中的团不会清理图片；仅查看图片或导出、预览存档不会延长保留期。
- 服务启动时及运行期间每分钟检查一次到期图片，图片清理与闲置房间的 7 天清理相互独立。原图过期或丢失后，恢复存档时会在原消息处显示占位符（附有文字说明时仍展示文字）。
- 若使用 Nginx 或 OpenResty 反向代理，建议将 `client_max_body_size` 设为至少 `32m`，以支持导入体积较大的全局存档 ZIP。
