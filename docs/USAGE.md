# 幕间使用手册

幕间是自托管的网页跑团工具，支持 D&D 5e（2014 / 2024 版）与克苏鲁的呼唤第 7 版（CoC 7th）。

## 本地运行

需要 Node.js 22.12.0 或更高版本。

```sh
npm ci
cp .env.example .env
npm run dev
```

打开 <http://127.0.0.1:5173>。Vite 前端会将 Socket.IO 与 `/api` 请求转发到 `127.0.0.1:3001`。同一浏览器的普通标签页共用同一会话身份，单机测试多名成员请使用不同浏览器或无痕窗口。

```sh
npm test          # 规则单元测试与真实 Socket.IO 集成测试
npm run build     # TypeScript 检查与生产构建
npm start         # 启动单端口生产服务
```

生产构建默认监听 <http://127.0.0.1:3001>。修改 `.env` 后需重启服务。字体已打包在本地构建产物中。

## 使用流程

1. 选择规则后创建房间，或输入 6 位房间码加入（单房最多 8 人）。D&D 首页头图可切换 2014 或 2024 版，房间与人物卡，以及配置文件和全局存档须使用同一版次（早期文件缺省按 2014 版读取）。
2. 创建者担任主持人（DM / KP），可选择「房内演绎」或「外部演绎」。
3. 主持人设置本团制卡限制；玩家新建、导入或载入人物卡，完成属性与技能分配后提交审核。房间内至少有一名玩家，全员在线并点击准备，且所有玩家人物卡均通过当前规则审核后，主持人即可点击开始。主持人席位不载入玩家人物卡。
4. 局内使用快速骰子与自定义骰式，或调用规则检定、状态与物品面板。主持人可暗骰、公布场景与发放物品，也可管理行动顺序，并通过「角色调整」修改玩家属性或技能的长期数值与临时效果。
5. 「房内演绎」开启公共图文聊天，「外部演绎」仅保留检定记录与局内工具；返回准备阶段后，主持人可切换演绎模式、移出离线成员或移交主持权。

界面支持浅色与深色主题切换；移动端可在「圆桌与记录」「局内工具」「同桌伙伴」三个视图间切换。点击房间顶部的「沉浸模式」可收起圆桌并放大记录区。

## 角色卡与制卡规则

- 玩家人物卡保存在浏览器 `localStorage` 中。跨设备使用前请导出备份：房间「我的角色」提供 JSON，制卡器支持 JSON 和 Markdown。
- D&D 5e：支持 4d6 取最高 3 颗生成六项属性，涵盖 2014 与 2024 版各 12 个职业。系统按版次校验职业技能与背景技能，并核对种族熟练和专精名额，自动计算技能加值与职业豁免。在「属性与状态」页可开启被动察觉（`10 + 当前察觉调整值`）。启用「法术与资源」和「装备与负重」后，可按版次管理法术准备与法术位，并自动计算护甲 AC、武器攻击和负重。
- CoC 7：支持 11 个职业的本职技能选择与职业点公式，同时计算兴趣点（`INT × 2`）和信用评级区间。KP 可开启「属性点上限」（限制不含幸运的八项属性总和，范围 195 至 720，超限卡可重掷或按比例下调），也可关闭「允许兴趣点投入职业技能（含信用评级）」以执行专点专用。
- 主持人可限制单项属性与技能范围，也可设置属性总和、允许职业与种族及额外熟练名额。准备阶段修改人物卡或变更房间规则后，需重新提交审核。详见 [规则与格式说明](RULES.md)。

## 局内角色调整

故事进行中，主持人可在「角色调整」面板修改玩家属性与技能的长期数值（如幕间技能成长）或添加可随时开关的临时效果。面板同时展示原始值、长期值与生效值，检定与豁免实时读取最新生效值。临时效果不会随回合或时间自动消失，需由主持人手动停用或清除。详见 [局内属性与技能调整](CHARACTER-ADJUSTMENTS.md)。

## 主持人备团与战斗工具

- CoC 主持人卡库：个人库保存在浏览器 IndexedDB 中，房间库保存在服务端；两者各上限 200 张、8 MiB。支持空白模板与原创示例，并提供属性骰式重掷和批量导入导出。详见 [KP 资料库说明](KEEPER.md) 与 [剧本提取与导入教程](KEEPER-IMPORT.md)。
- D&D 数据块与战斗：支持管理怪物数据块、生成多个独立 HP 的参战个体，以及排定先攻顺序（含 2014 与 2024 版突袭规则）。开启「自动扣减生命值」后，可按目标结算定向攻击与临时 HP，并处理抗性易伤及 CoC 近战对抗护甲。详见 [D&D 数据块教程](DND-STATBLOCKS.md) 与 [战斗操作说明](COMBAT.md)。
- 法术书与专长：在「主持人工具集」中按 2014 或 2024 版搜索法术与专长，支持收藏个人清单并导出备份。详见 [法术书与专长](DND-REFERENCES.md) 与 [版次说明](DND-EDITIONS.md)。
- 角色准备与遭遇预案：支持局内施法扣位与队伍批量休息，可指定伙伴（魔宠 / 召唤物）归属，并按波次编排和载入遭遇预案。详见 [角色准备与备团](CHARACTER-PREPARATION.md)、[法术与资源](DND-MAGIC.md) 与 [核心装备资料](DND-EQUIPMENT.md)。
- 地图册与场景集：个人库与房间库各上限 50 本（8 MiB），单本最多 50 张地图、300 个场景。支持按地图筛选场景并将公开描述发布到桌面。详见 [地图册与场景集](ATLAS.md)。

## 图片消息与存储目录

房内演绎开始后，成员可在聊天区上传或粘贴 PNG / JPEG / GIF / WebP 图片（单张上限 8 MiB）。

- 直接运行时，可在 `.env` 中设置 `IMAGE_DIR`（默认 `DATA_DIR/images`）；Docker Compose 默认挂载 `image-data` 卷，也可通过 `IMAGE_STORAGE_PATH` 指定宿主机目录（需允许容器 UID 1000 读写）。
- 图片在最后一次跑团结束 14 天后自动清理，重新开团会重置计时，进行中的团不会清理图片。
- 备份或迁移服务器时，请同时复制 `DATA_DIR`（含 `images.json`）与图片目录。反向代理需将请求体上限设为不少于 12 MiB（如 `client_max_body_size 12m`；若需导入大型全局存档 ZIP，建议设为 `32m`）。

## 房间配置与全局存档

- 房间配置：主持人在「房间配置」中可导出 JSON 或 Markdown，内容包含房名、规则与演绎模式，以及制卡限制和当前公开场景，用于在创建新房间或准备阶段复用设置。
- 全局存档：主持人在「全局存档」中可将整局状态导出为 ZIP 压缩包，内含角色、修正与备团资料，以及战斗进度和全部可用聊天记录。下次在「创建房间」页选择「从全局存档续团」即可恢复原房间阶段，玩家使用一次性席位恢复码认领各自角色。详见 [全局存档与续团](SESSION-ARCHIVE.md)。

## Gemini 灵感助手

在 `.env` 中配置密钥与模型 ID 并重启服务后，主持人可在局内使用灵感生成窗口。

```dotenv
GEMINI_API_KEY=你的服务端密钥
GEMINI_MODEL=gemini-3.8-flash
```

仅当主持人点击生成时才会调用 Gemini API，请求内容包含当前公开场景、角色姓名与职业，以及最近 12 条公开文字消息和主持人的提问（不发送图片、暗骰结果或会话凭证）。生成结果仅显示在主持人端，两次请求至少间隔 10 秒。

## 持久化与部署

- 房间状态保存在 `DATA_DIR/rooms.json`（默认最多保留 200 个房间，全员离线且连续 7 天无活动的房间会自动清理）。直接关闭网页仍保留座位，点击「离开房间」才会释放座位。
- 使用 Docker 部署时，执行 `cp .env.example .env`、配置 `ALLOWED_ORIGINS` 后运行 `docker compose up -d --build`。Compose 默认监听宿主机 `127.0.0.1:3001`，前置 Nginx 或 OpenResty 反向代理需开启 WebSocket Upgrade，并将 `proxy_read_timeout` 设为不少于 75 秒。

## 浏览器验收

仓库包含基于 Playwright 的端到端测试脚本，覆盖双人建卡与审核、KP 与 D&D 备团库，以及回合战斗与自动扣血；同时检查局内数值调整、地图集与房间配置，并验证全局存档 ZIP 导入导出和 IndexedDB 并发事务。

运行前先执行 `npm run build`，再在另一个终端运行 `npm run dev` 并保持服务开启。默认脚本和卡库 IndexedDB 测试使用 5173 端口，下面指定 3001 端口的脚本使用构建后的页面。测试会创建房间和图片，建议使用隔离的测试数据目录。

```sh
python3 -m venv .venv
.venv/bin/pip install -r tests/requirements.txt
.venv/bin/playwright install chromium
.venv/bin/python tests/e2e.py
.venv/bin/python tests/e2e_review.py
.venv/bin/python tests/e2e_toolkit.py
.venv/bin/python tests/e2e_encounter.py
.venv/bin/python tests/e2e_adjustments.py
.venv/bin/python tests/e2e_preparation.py --url http://127.0.0.1:3001
.venv/bin/python tests/e2e_archive.py --url http://127.0.0.1:3001
.venv/bin/python tests/e2e_keeper_storage.py
.venv/bin/python tests/e2e_dnd_reference_storage.py
```

测试报告与截图输出在 `test-results/` 目录。
