# 局内属性与技能调整

故事进行中，主持人可在房间右侧打开「角色调整」并选择玩家角色，也可点击圆桌席位或同桌伙伴，在人物详情中打开「调整属性与技能」（移动端从「局内工具」进入）。准备阶段此面板只读，制卡修改请使用角色编辑器。

## 数值层级

| 层级 | 说明                                               |
| ---- | -------------------------------------------------- |
| 原始 | 制卡时的属性与技能，保留初始分配记录               |
| 长期 | 原始值叠加主持人记录的成长或永久损伤               |
| 生效 | 长期值再叠加所有已启用的临时效果，角色检定使用此值 |

### 修改长期数值

选中属性或技能，切换到「长期数值」，填写目标数值与可选原因。保存后实时同步给房间成员，并写入房间公开日志。点击「重置长期修正」仅清除该项的长期变更，其余项目与临时效果保留。

D&D 技能由当前关联属性与原有熟练、专精自动计算，再叠加技能修正（长期技能输入值不含临时属性变化）。例如敏捷 18、隐匿原本 +4，将长期隐匿改为 +6 即代表额外 +2；若此后敏捷临时降至 14，隐匿生效值变为 +4，停用敏捷惩罚后恢复为 +6。

CoC 技能直接按目标百分比记录。例如侦查从 50 成长至 60，无需返回制卡器重算职业点或兴趣点。局内修改 DEX 或 EDU 后，已习得的闪避与母语不会自动改写，需由 KP 分别调整。

### 管理临时效果

选中目标项目，填写正负修正、效果名称与结束条件说明（如「离开瞭望台时」），确认生效值预览后保存。

效果列在面板下方，支持停用、重新启用或移除；点击「清除全部」并在确认后可移除所有临时效果，长期数值保持不变。结束条件仅作为文字提醒，换场景、推进回合或重启服务均不会自动停用效果，需由主持人手动开关。多项临时效果按加减法直接叠加。

## 联动与数值边界

- 属性检定、技能检定与 D&D 属性豁免均读取最新生效值，CoC 同时更新普通、困难与极难成功阈值。
- 重新排定先攻时读取最新敏捷，进行中的行动顺序保持不变。
- 战斗面板的玩家体质检定、D&D 专注豁免及 CoC 近战对抗默认读取角色当前数值。主持人手动修改输入值后保留手填值，点击「使用角色最新加值」可恢复跟随角色。
- D&D 定向战斗攻击中选择已持用武器时，按当前属性、熟练与装备加值计算命中与伤害；法术攻击加值与豁免 DC 同样读取当前施法属性。启用 D&D 装备联动后，敏捷等属性变化会同步更新派生 AC。
- 局内调整仅作用于玩家角色，不会自动修改 HP、MP 或 SAN 上限（如 CoC 克苏鲁神话变动后的 SAN 上限需由主持人另行修改）。

数值边界：D&D 属性为 1 至 30，技能加值为 -100 至 100；CoC 属性为 0 至 100，技能为 0 至 100（克苏鲁神话上限 99）。单项临时修正范围为 -100 至 100，单张角色卡最多保存 30 个临时效果。若停用或移除某项效果会导致剩余叠加值越界，操作会被拒绝，可先清除全部临时效果回到长期值。

制卡点预算与房间制卡限制仅校验原始制卡记录，局内成长与临时效果不消耗制卡点。返回准备阶段会重置准备与审核状态并保留修正记录，主持人可在审核页一并核对原始分配与局内修正。

## 保存与导出

每次调整都会即时写入房间状态并记入公开日志，服务端按角色版本号校验并发冲突；玩家可从「我的角色」或人物详情导出最新 JSON，或在制卡器中导出 Markdown。导出文件保留原始属性与技能分配，同时附带长期数值和临时效果，重新导入入房时须经主持人再次审核。

### 文件字段

`schemaVersion: 1` 人物卡通过可选的 `adjustments` 字段记录局内变更，旧卡不含此字段仍可正常读取。

```json
{
  "adjustments": {
    "permanent": [{ "target": "skill", "key": "spotHidden", "amount": 10, "reason": "幕间成长" }],
    "temporary": [
      {
        "id": "clear-view",
        "name": "视野开阔",
        "endCondition": "离开瞭望台时",
        "enabled": true,
        "changes": [{ "target": "skill", "key": "spotHidden", "amount": 15 }]
      }
    ]
  }
}
```

这只是字段片段，不能单独作为人物卡导入；完整文件仍需包含角色身份、原始属性、技能与分配记录等必需字段。
