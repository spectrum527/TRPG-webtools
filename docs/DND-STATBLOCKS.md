# D&D 5e 主持人数据块

数据块库用于备团、查阅 NPC 与怪物资料，以及在局内生成独立参战个体。个人数据块保存在当前浏览器的 IndexedDB 数据库 `interlude-dnd-library` 中，与玩家人物卡及 CoC 资料卡分开存储。

## 从剧本提取与导入

1. 在「主持人工具集」选择与剧本一致的 D&D 2014 或 2024 版次，进入个人数据块库，打开「AI 提取与导入指南」复制或下载对应版次的提示词与模板。
2. 将提示词连同剧本 PDF、页图或正文交给外部 AI Agent，标明规则版次与章节，并给出提取对象和页码范围。
3. 让 AI 输出仅含单个 JSON 代码块的 Markdown 文件。核对提取出的 NPC / 怪物数量，抽查名称、AC 与 HP，核对生命骰、攻击加值和伤害骰，并确认豁免 DC、能力次数与充能条件，确保缺失与冲突已记入 `notes`。
4. 将文件保存为 UTF-8 编码的 `.md` 或 `.json`，在数据块库点击「导入资料集」（单批上限 200 张，文件上限 8 MiB）。在预览页与编辑页复核无误后保存。
5. 进入对应版次的 D&D 房间担任 DM 后，可将个人库资料作为独立副本带入房间，也可将房间内的数据块存回个人库。
6. 战斗需要多个同类生物时，在房间右侧「场景与回合」中从房间库生成参战个体，各体独立记录 HP、状态与能力次数。

2014 版可直接参考以下文件，2024 版可在网站内切换版次后下载。

- [原创两卡 Markdown 模板](templates/dnd-import.md)
- [完整中文 LLM 提取提示词](templates/dnd-extraction-prompt.md)

## 字段保留规则

- 固定 HP 与生命骰分别保存：常规数据块给出的 HP 上限写入 `maxHp`，明确记录的当前剩余值写入 `hp`。若来源仅给出 `HP 27`，导入后 `maxHp` 为 `27`、`hp` 为 `null`。
- `hitDice` 与动作中的 `damage` 保留原文字符串（如 `5 (1d6 + 2) 钝击伤害`），导入时不自动掷骰，也不根据生命骰均值改写 `maxHp` 或根据 CR 推算 XP。
- 原文未给出的数值保持 `null`，未给出的文本保持空字符串，明确为 `0` 的数值原样保留。来源页码与字段依据，以及缺失项和版本冲突统一记入 `notes`。

## 外部 AI 提取简式

外部提取格式使用 `documentType: "dnd-source"`，仅需填写 `name`、`kind`（`npc` 或 `monster`）及已确认的字段；2024 版资料在顶层或单卡中加入 `"dndEdition": "2024"`（省略时按 2014 读取）。系统在整批校验通过后自动补齐 ID、时间戳与空字段。最小可导入示例如下。

```json
{
  "schemaVersion": 1,
  "documentType": "dnd-source",
  "rule": "dnd",
  "cards": [
    {
      "name": "尚未详录的访客",
      "kind": "npc",
      "source": "自备剧本 · 页码未提供",
      "notes": "缺失：来源仅提供人物名称，其余数值待核对。"
    }
  ]
}
```

每次导入 `dnd-source` 简式都会生成新卡片 ID。网站导出的完整备份格式使用 `dnd-statblock`（单卡）或 `dnd-collection`（资料集），保留原有 ID、时间戳与全部字段，支持 JSON 与 Markdown 再次导入。

## 字段与边界

| 字段                                                                      | 类型与上限                                                                           |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `name` / `kind`                                                           | 简式必填。名称 1 至 120 字符；类型为 `npc` 或 `monster`                              |
| `size` / `creatureType` / `alignment`                                     | 体型、生物类型与阵营文本，上限分别为 120 / 200 / 120 字符                            |
| `description`                                                             | 外观、身份或场景说明，上限 4000 字符                                                 |
| `ac` / `acNotes`                                                          | 护甲等级 0 至 100 或 `null`；护甲补充说明上限 2000 字符                              |
| `hp` / `maxHp` / `hitDice`                                                | 当前值与上限各为 0 至 100000 或 `null`；生命骰文本上限 240 字符                      |
| `speed`                                                                   | 移动速度与方式文本，上限 500 字符                                                    |
| `attributes`                                                              | `str` / `dex` / `con` / `int` / `wis` / `cha`，每项 1 至 30 或 `null`                |
| `saves`                                                                   | 六项属性的豁免总加值，范围 -100 至 100，未知项省略                                   |
| `skills`                                                                  | 最多 100 项，每项含 `name` 与整数 `value`（-100 至 100）                             |
| `senses` / `languages`                                                    | 感官与语言文本，各上限 2000 字符                                                     |
| `challenge` / `xp`                                                        | CR 字符串（空或 `0` / `1/8` / `1/4` / `1/2` / `1`–`30`）；XP 为 0 至 1000000000 或 `null` |
| `resistances` / `immunities` / `vulnerabilities` / `conditionImmunities`  | 伤害抗性、免疫与易伤，以及状态免疫文本，各上限 4000 字符                             |
| `traits` / `actions` / `reactions` / `legendaryActions`                   | 特性与动作，以及反应和传奇行动数组，每组最多 50 项                                   |
| `spellcasting` / `lairActions`                                            | 施法与巢穴行动文本，各上限 12000 字符                                                |
| `legendaryActionCount`                                                    | 每轮传奇行动次数，0 至 100 或 `null`                                                 |
| `notes` / `source` / `tags`                                               | 私密笔记上限 24000 字符；来源上限 2000 字符；标签最多 30 个（每个 1 至 60 字符）     |

四类行动项共用以下字段结构（简式中仅 `name` 必填）。

| 行动项字段                | 类型与上限                                                           |
| ------------------------- | -------------------------------------------------------------------- |
| `name` / `description`    | 名称 1 至 120 字符；效果与限制说明上限 6000 字符                     |
| `attackBonus`             | 命中总加值，-100 至 100 或 `null`                                    |
| `damage`                  | 伤害骰式与类型原文，上限 1000 字符                                   |
| `saveDc` / `saveAbility`  | 豁免 DC 为 0 至 100 或 `null`；豁免属性说明上限 120 字符             |
| `uses` / `recharge`       | 可用次数为 0 至 100000 或 `null`；充能或恢复条件上限 200 字符        |

## 常见导入报错

| 报错情况                                   | 修正方式                                                       |
| ------------------------------------------ | -------------------------------------------------------------- |
| 含 `id` / `level` / `templateId` 等未知键  | 在 `dnd-source` 中移除这些键，必要说明写入 `notes`             |
| CR 格式无效                                | 改为 `"1/4"` 或 `"0"` 等字符串，未给出时填 `""`                |
| 属性超出 1 至 30 或填入了文字              | 核对原文与 OCR，特殊描述移入 `notes`，属性字段留 `null`        |
| 当前 HP 大于 `maxHp`                       | 核对当前值、上限与临时生命值说明                               |
| 技能缺少 `value`                           | 原文仅列出技能名称而无加值时，移入 `notes`                     |
| Markdown 内含多个 JSON 代码块              | 仅保留一个完整的 JSON 代码块，移除注释与尾随逗号               |
| 单批超过 200 张或文件超过 8 MiB            | 按章节拆分为多份文件分批导入                                   |
