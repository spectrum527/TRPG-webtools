# 从剧本快速导入 NPC 与怪物

本流程用于将 CoC 第 7 版剧本中的人物与生物整理为主持人（KP）的独立资料卡，支持导入姓名、属性与属性骰式，同时记录攻击、技能与特殊能力及来源笔记。

## 导入步骤

1. 在主侧边栏进入「主持人工具集」，点击「提取提示词、模板与教程」复制完整提取提示词（也可在个人卡库中打开「AI 提取与导入指南」，或直接查看仓库中的[提示词文件](templates/keeper-extraction-prompt.md)）。
2. 将提示词连同 CoC 第 7 版剧本 PDF、页图或文字交给外部 LLM，说明提取范围（如章节、页码或指定人物）。
3. 让 LLM 输出仅包含一个 `json` 代码块的 Markdown。核对人物数量、名称与页码，并检查 `notes` 中的字段依据和冲突说明，留意 OCR 易错的数字与乘号。
4. 将内容保存为 UTF-8 编码的 `.md` 或 `.json` 文件，在个人卡库点击「导入资料集」（单批上限 200 张，文件上限 8 MiB）。
5. 打开导入的卡片复核。`keeper-source` 格式每次导入均生成新 ID；如需按基础公式重算派生值或按骰式生成新个体，可在卡片编辑页使用重算或重掷功能。
6. 进入 CoC 房间担任 KP 后，在个人卡库点击「带入当前房间」或「全部带入房间」，也可将房间内的卡片存回个人备团库。

初次尝试可下载[原创两卡模板](templates/keeper-import.md)并直接通过「导入资料集」预览格式。

## 提取字段映射

顶层结构包含 `documentType: "keeper-source"`、`schemaVersion: 1`、`rule: "coc"` 与 `cards` 数组。单张卡片仅必填 `name`、`kind` 与 `category`，其余空白字段、ID 与时间戳由系统补齐。

| 资料项                | 对应字段与填法                                                                      |
| --------------------- | ----------------------------------------------------------------------------------- |
| 人类 NPC              | `kind: "npc"`，分类通常填 `category: "human"`                                       |
| 怪物与实体            | `kind: "monster"`，分类填 `mythos` / `deity` / `traditional` / `beast` / `custom`   |
| 固定属性              | 写入 `attributes`，键名为 `str` / `con` / `siz` / `dex` / `app` / `int` / `pow` / `edu` |
| 属性生成骰式          | 写入 `attributeRolls`，仅记录原文明确给出的骰式                                     |
| 模组给定的 HP / MP    | 写入 `maxHp` / `maxMp`，保留模组设定上限                                            |
| 当前剩余 HP / MP      | 写入 `hp` / `mp`，须同时提供对应上限；仅知当前值时先记入 `notes`                    |
| 攻击方式              | 写入 `attacks` 数组，记录名称与成功率，以及伤害文本和说明                           |
| 技能                  | 写入 `skills` 数组，记录技能名称与最终百分比                                        |
| 来源页码与缺失说明    | `source` 记录书名与页码，`notes` 记录字段依据、缺失项与版本冲突                     |

原文未给出的数值填 `null` 或省略，明确为 `0` 的数值原样保留；固定属性与属性骰式可同时保存，导入时不会自动掷骰或用公式覆盖模组给定的 `maxHp`。

## 常见导入报错

| 报错情况                                 | 修正方法                                                             |
| ---------------------------------------- | -------------------------------------------------------------------- |
| `attributes.str` 类型错误                | 将字符串 `"50"` 改为数字 `50`，未知时填 `null`                       |
| 包含 `id` / `templateId` 等未知字段      | 移除未知字段，`keeper-source` 由网站自动生成 ID 与时间戳             |
| 骰式 `2d6+6*5` 存在运算顺序歧义          | 改为带括号的 `(2d6+6)*5`；无法确认原文含义时移入 `notes` 并留空骰式  |
| 当前 HP 大于上限或缺少上限               | 核对原文当前值与上限，无法确认的部分记入 `notes`                     |
| 技能缺少 `value`                         | 仅保留有明确成功率的技能项，无数值的技能说明移入 `notes`             |
| Markdown 内含多个 JSON 代码块            | 仅保留一个要导入的 JSON 代码块                                       |
| 单批超过 200 张或文件超过 8 MiB          | 按章节或场景拆分为多份文件分批导入                                   |

网站导出的完整备份文件（`keeper-card` 与 `keeper-collection`）包含卡片 ID 与时间戳，可直接再次导入。KP 卡库的数据结构与分类说明见 [KP 资料库说明](KEEPER.md)。
