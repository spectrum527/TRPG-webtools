# 幕间

幕间是一个网页版的跑团工具，自己部署到服务器上，和朋友在浏览器里开团。支持 **D&D 5e（2014 / SRD 5.1）** 和 **CoC 第 7 版**。

主持人在里面备团、审人物卡，玩家在里面建卡、掷骰、发言。一次没跑完，可以导出存档，下次接着跑。幕间负责记录和计算，规则怎么裁、故事往哪走，还是由主持人和玩家自己决定。

[本地试用](#本地试用) · [功能](#功能) · [部署](#部署) · [数据存在哪里](#数据存在哪里) · [文档](#文档)

## 功能

**开团前**

- 主持人可以建 CoC 的 NPC／怪物库和 D&D 数据块库，也可以整理地图和场景。资料能用 JSON 或 Markdown 导入导出。
- 项目附带一份提示词，复制给 AI，可以把剧本里的 NPC 和场景提取成可导入的格式。
- 房间用 6 位房间码加入，最多 8 人，其中一个席位是主持人（DM／KP）。房间配置也能导出，下次直接导入。

**建卡和审核**

- 玩家生成属性，分配技能或熟练项，然后提交给主持人审核。
- 主持人可以先设定制卡限制，例如属性上限。不符合当前规则的卡不能开团。

**跑团中**

- 骰子由服务器掷，玩家改不了结果。骰式可以自定义，D&D 有优势／劣势，CoC 有奖励骰／惩罚骰和理智检定。主持人可以暗骰。
- 可以发文字和图片，主持人可以把场景公开给所有人。有沉浸模式、深色主题和手机布局。
- 战斗时有行动顺序。同一种 NPC 可以拆成多个个体分别记血量。角色的资源和物品也在这里记，长期数值调整和临时效果可以在局内加。
- 如果你们在别的聊天软件里或线下演绎，可以只用幕间掷骰和记状态。

**暂停和续团**

- 房间状态保存在服务器上，断线后重新打开页面就能回到原来的座位。
- 可以把整局导出成一个 ZIP 存档。恢复存档后，每个玩家用一次性的席位码认领自己的角色。

### 目前不做的事

- D&D 只覆盖 SRD 5.1 的 12 个职业；CoC 覆盖 11 个职业，支持职业点和兴趣点分配。
- 法术、装备效果和升级需要人工核对。
- 攻击命中后不会自动扣血，临时效果到时间也不会自动消失，需要手动停用。
- 地图册只整理文字描述和场景资料，不生成战棋地图。

具体范围见[规则与格式](docs/RULES.md)和[战斗说明](docs/COMBAT.md)。

## 本地试用

需要 Node.js 22.12.0 或更高版本。在项目目录运行下面三条命令。

```sh
npm ci
cp .env.example .env
npm run dev
```

打开 <http://127.0.0.1:5173>。这个命令会同时启动前端（Vite）和房间服务，前端把 `/api` 和 Socket.IO 请求转发到 `127.0.0.1:3001`。

一局的大致流程如下。

1. 选规则，创建房间。其他人选同样的规则，输入房间码加入。
2. 主持人设好制卡要求。玩家新建或导入人物卡，按本团规则分配技能或熟练项后提交审核。
3. 开团需要三个条件同时满足。房间里至少有一名玩家；所有人在线并点了准备；每个玩家的卡都按当前制卡规则通过了审核。满足后主持人点开始。
4. 跑团时用局内工具掷骰和发场景，顺手记下角色状态。结束前导出存档，下次用它续团。

想在一台电脑上模拟两个人，第二个人要用另一个浏览器或无痕窗口。同一浏览器开新标签页，还是同一个身份。主持人席位不会载入玩家人物卡。

正式运行要先构建，再启动。

```sh
npm run build
npm start
```

默认地址是 <http://127.0.0.1:3001>，健康检查接口是 `/api/health`。改了 `.env` 要重启服务才生效。字体已经打包在项目里，不需要联网下载。

## 部署

仓库里有 [Dockerfile](Dockerfile) 和 [compose.yaml](compose.yaml)，可以直接用 Docker 跑。

```sh
cp .env.example .env
# 把 .env 里的 ALLOWED_ORIGINS 改成你的网站地址
docker compose up -d --build
```

Compose 只监听宿主机的 `127.0.0.1:3001`，数据存在 `room-data` 和 `image-data` 两个卷里。要让外网访问，在前面加一层 Nginx 或 OpenResty 配 HTTPS。反向代理有三项设置必须改。

- 开启 WebSocket Upgrade
- `proxy_read_timeout` 不少于 75 秒
- 请求体上限不少于 12 MiB，例如 `client_max_body_size 12m`

### 环境变量

| 配置项                            | 作用                                                                                                      |
| --------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `HOST` / `PORT`                   | 直接运行时的监听地址和端口，默认 `127.0.0.1:3001`。Compose 容器内固定为 `0.0.0.0:3001`                    |
| `DATA_DIR`                        | 直接运行时的数据目录，默认 `./data`。Compose 用 `/app/data`                                               |
| `IMAGE_DIR`                       | 直接运行时的图片目录，不填就用 `DATA_DIR/images`                                                          |
| `IMAGE_STORAGE_PATH`              | 只在 Compose 下有用，指定宿主机上的图片目录。不填就用 `image-data` 卷。自定义目录要让容器 UID 1000 能读写 |
| `ALLOWED_ORIGINS`                 | 允许访问的网站地址，要写完整（含 `https://`），多个用英文逗号隔开                                         |
| `GEMINI_API_KEY` / `GEMINI_MODEL` | 主持人灵感助手，可选。不填密钥就不启用                                                                    |

部署完建议检查三件事。健康检查接口能访问；用两个浏览器进同一个房间，看消息是否同步；重启服务后，页面能否自动重连。

现在的存储方式是写本地文件，适合一台服务器跑一个实例的小站。要跑多个实例，需要共享存储，并给 Socket.IO 配 adapter。

## 数据存在哪里

**浏览器里**

人物卡存在 `localStorage`，备团资料存在 IndexedDB，换设备不会自动同步。换电脑或清浏览器数据前，记得先导出。

把备团资料带进房间时，房间里拿到的是一份副本。在局内改了，不会影响你浏览器里的原稿。

**服务器上**

房间状态写在 `DATA_DIR/rooms.json`。关掉页面，座位还在；点「离开房间」才会让出座位。服务器默认最多保留 200 个房间，所有人都离线且 7 天没有活动的房间会被删除。

**谁能看到什么**

同一房间的人都能看到玩家的人物资料和笔记。只有当前主持人能看到 NPC／怪物库、地图的私密笔记和 AI 灵感。

主持人暗骰时，其他人能看到"主持人掷了骰"以及骰式或检定名称，看不到点数和结果。登录凭证由服务器单独校验，不会广播给房间里的其他人。

**图片**

支持 PNG、JPEG、GIF 和 WebP，每张不超过 8 MiB。最后一次跑团结束 14 天后，图片会被清理；期间再开团，期限重新计算。正在进行的团里的图片不会被删。图片的清理和房间的清理分开计算。

**存档 ZIP**

存档里有房间配置、角色、数值调整、备团资料、战斗进度和全部可用的聊天记录，但不含图片文件本身。默认只保存图片在服务器上的引用；如果取消勾选图片，要为每张图写一段文字描述代替。

所以要完整备份或迁移服务器，需要同时复制整个 `DATA_DIR`（包括 `images.json`）和图片目录。

身份、图片迁移和存储位置的细节见[使用手册](docs/USAGE.md)和[存档续团教程](docs/SESSION-ARCHIVE.md)。

## 可选：Gemini 灵感助手

主持人卡壳时，可以让 Gemini 给点建议或写一段示例旁白。开启方法是在 `.env` 里填 `GEMINI_API_KEY`，把 `GEMINI_MODEL` 改成你的账号能用的模型 ID，然后重启服务。`.env.example` 里的模型 ID 只是示例，项目不会检查你的账号能不能用。

只有主持人点「生成」时才会请求 Gemini。发出去的内容有当前场景、角色的名字和职业、最近 12 条公开文字发言，以及主持人这次的问题。图片、登录凭证、暗骰和完整角色笔记不会发出去。

生成的内容只出现在主持人自己的窗口里，不会自动发到公共记录。API 密钥只存在服务器上。两次请求至少间隔 10 秒，超时会自动中断。

备团库里那份提取提示词和这个助手无关，你可以拿去给任何 AI 用。导入前请核对数值，并检查公开描述里有没有剧透。

## 开发

用到的技术：React 19、TypeScript、Vite 7、Express 5、Socket.IO 4。

```sh
npm test          # 规则单元测试，以及连真实 Socket.IO 的集成测试
npm run typecheck # TypeScript 类型检查
npm run build     # 类型检查后打包
```

[GitHub CI](.github/workflows/ci.yml) 会在 Node.js 22 和 24 上跑测试和构建，审计生产及开发依赖，并在 Chromium 里走一遍浏览器流程（包括原生 IndexedDB），最后检查 Docker 镜像能否正常启动。

浏览器测试脚本的安装和运行方法见[使用手册](docs/USAGE.md#浏览器验收)，结果保存在 `test-results/`。Gemini 相关测试用的是模拟接口，接真实服务要自己配密钥再测。

```text
src/       页面、人物卡编辑器、房间工具、浏览器存储
shared/    类型定义、规则计算、点数分配、导入校验
server/    房间服务、权限、文件存储、Gemini 代理
tests/     规则测试、多人会话测试、浏览器测试
docs/      使用说明、规则、模板、README 图片
```
