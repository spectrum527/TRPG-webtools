# 幕间

幕间是自托管的网页跑团工具，部署在自己的服务器上即可和朋友在浏览器里开团。支持 D&D 5e（2014 / 2024 版，各含 12 个基础职业）和克苏鲁的呼唤第 7 版（CoC 7th，含 11 个职业）。

主持人在浏览器中维护 CoC 的 NPC 与怪物库，管理 D&D 数据块和遭遇预案，也可按版次检索法术书与专长，或整理文字场景地图册。备团资料支持 JSON 与 Markdown 导入导出，[`docs/templates/`](docs/templates/) 提供提取提示词，可将剧本中的人物和场景整理为可导入文件。玩家在线生成属性，分配技能点或熟练项；D&D 角色可准备法术、管理法术位与职业资源，穿戴装备后自动计算 AC、武器攻击和负重。角色卡提交后由主持人审核。

房间使用 6 位房间码加入，单房最多 8 人（含 1 个主持人席位）。局内由服务端掷骰，提供自定义骰式，包含 D&D 优势与劣势、CoC 奖励骰与惩罚骰，并支持理智检定和主持人暗骰。房间内可发送文字与图片，也可由主持人公开场景，界面提供深色主题、沉浸模式和移动端布局。战斗面板可逐人掷先攻（含 2014 / 2024 两版突袭规则），将同名 NPC 拆为多个独立血量个体；开启自动扣血后，按目标结算伤害与临时 HP，同时计算指定的抗性、易伤和 CoC 护甲。局内可记录施法消耗与队伍批量休息，指定召唤物归属，或添加永久数值修改和手动开关的临时效果。单次未跑完时可导出整局 ZIP 存档，恢复后玩家凭一次性席位码认领角色。

## 本地运行

需要 Node.js 22.12.0 或更高版本。

```sh
npm ci
cp .env.example .env
npm run dev
```

打开 <http://127.0.0.1:5173>。该命令会同时启动 Vite 前端与房间服务，并将 `/api` 和 Socket.IO 请求转发到 `127.0.0.1:3001`。

生产环境先构建再启动。

```sh
npm run build
npm start
```

默认监听 <http://127.0.0.1:3001>，健康检查接口为 `/api/health`。修改 `.env` 后需重启服务。字体已内置在项目中，运行时无需联网加载。

## 开团流程

1. 选择规则并创建房间。D&D 首页头图可切换 2014 或 2024 版，房间、人物卡与导入文件须使用同一版次。其他成员选择相同规则和版本，输入 6 位房间码加入。同一浏览器的新标签页共用同一身份，单机测试多席位请使用不同浏览器或无痕窗口。
2. 主持人设置属性上限等制卡限制。玩家新建或导入人物卡，按房间规则完成技能、法术与装备配置后提交审核。主持人席位不载入玩家人物卡。
3. 房间内至少有一名玩家，所有人在线并点击准备，且全部玩家人物卡均通过审核后，主持人即可点击开始。
4. 局内使用面板工具掷骰或切换公开场景，并在战斗中推进回合与结算休息。房间配置可导出供下次建团复用；要恢复本局进度，请在结束前导出整局 ZIP 存档。

## Docker 部署

仓库包含 [Dockerfile](Dockerfile) 和 [compose.yaml](compose.yaml)。

```sh
cp .env.example .env
# 将 .env 中的 ALLOWED_ORIGINS 改为站点完整地址（含 https://）
docker compose up -d --build
```

Compose 默认只监听宿主机的 `127.0.0.1:3001`，数据保存在 `room-data` 和 `image-data` 两个卷中。公网访问需在前端配置 Nginx 或 OpenResty 反向代理并启用 HTTPS。反向代理需开启 WebSocket Upgrade，将 `proxy_read_timeout` 设为不少于 75 秒，并将请求体上限设为不少于 12 MiB（如 `client_max_body_size 12m`）。

### 环境变量

| 配置项                            | 作用                                                                                                   |
| --------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `HOST` / `PORT`                   | 直接运行时的监听地址和端口，默认 `127.0.0.1:3001`。Compose 容器内固定为 `0.0.0.0:3001`                 |
| `DATA_DIR`                        | 直接运行时的数据目录，默认 `./data`。Compose 内固定为 `/app/data`                                      |
| `IMAGE_DIR`                       | 直接运行时的图片目录，默认 `DATA_DIR/images`                                                           |
| `IMAGE_STORAGE_PATH`              | 仅 Compose 使用，指定宿主机图片目录；留空则使用 `image-data` 卷。自定义目录需允许容器 UID 1000 读写    |
| `ALLOWED_ORIGINS`                 | 允许访问的完整站点地址（含 `https://`），多个地址用英文逗号隔开                                        |
| `GEMINI_API_KEY` / `GEMINI_MODEL` | 可选。配置密钥后启用主持人灵感生成窗口，留空则关闭。需将 `GEMINI_MODEL` 改为当前账号可用的模型 ID      |

## 数据与存储

人物卡保存在浏览器的 `localStorage`，备团资料库保存在 IndexedDB，不同设备之间不会自动同步。更换设备或清理浏览器数据前请先导出文件。带入房间的备团资料均为副本，局内修改不会改动浏览器中的原稿。

房间状态写入服务端 `DATA_DIR/rooms.json`。直接关闭页面仍保留座位，点击「离开房间」才会让出席位。服务端默认最多保留 200 个房间，所有人离线且连续 7 天无活动的房间会被删除。

聊天图片支持 PNG / JPEG / GIF / WebP，单张不超过 8 MiB。图片在最后一次跑团结束 14 天后清理，期间再次开团会重新计时，进行中的团不会清理图片。

存档 ZIP 会打包房间配置、人物卡与数值调整，同时收入备团资料、战斗进度和聊天记录。存档默认只记录图片在服务端的引用，不包含原图；若导出时取消勾选图片，则需要为每张图填写替代文字说明。完整备份或迁移服务器时，请同时复制整个 `DATA_DIR`（含 `images.json`）和图片目录。

## 开发

前端使用 React 19、TypeScript 和 Vite 7，服务端使用 Express 5 和 Socket.IO 4。

```sh
npm test          # 规则单元测试与 Socket.IO 集成测试
npm run typecheck # TypeScript 类型检查
npm run build     # 类型检查并打包生产文件
```

浏览器端到端测试脚本的运行方式见[使用手册](docs/USAGE.md#浏览器验收)，测试输出保存在 `test-results/`。

```text
src/       前端页面与人物卡编辑器，房间面板与浏览器存储
shared/    共享类型与规则计算，点数分配与导入校验
server/    房间服务与权限校验，文件存储与 Gemini 代理
tests/     规则单元测试与多人会话测试，浏览器端到端测试
docs/      使用文档与规则说明，导入模板与 README 图片
```
